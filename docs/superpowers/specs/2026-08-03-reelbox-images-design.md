# Reelbox — сохранение картинок и каруселей

Дата: 2026-08-03
Статус: реализовано; границы сужены после живого прогона 04.08.2026

## Пересмотр 04.08.2026

Живой прогон снял три решения этой спеки.

**Пакетное сохранение карусели убрано.** Кнопка с числом слайдов не отвечала на
вопрос «а какие именно восемь сейчас уедут», и остановить начатое было нельзя.
Вместо доработки пакета он снят целиком: кадры сохраняются по одному, и тогда
вопрос не возникает вовсе.

**Лента и сетка профиля убраны.** На плитке под курсором лежит миниатюра, из
неё вышел бы файл хуже оригинала, а какой пост имеется в виду — вопрос догадки.
Реальный обиход всё равно начинается с открытия поста целиком. Кнопка теперь
живёт только на открытом посте.

**Рамка на цели убрана.** Она нужна была, чтобы различать плитки в сетке. Без
сетки различать нечего: на открытом посте цель одна и очевидна.

Ниже текст приведён в соответствие с этими решениями.

Продолжение [2026-08-03-reelbox-design.md](2026-08-03-reelbox-design.md). Там
описано сохранение Reels, здесь — расширение того же механизма на картинки.

## Задача

Антон собирает референсы не только видео. Картинки из постов, из каруселей и
из сторис нужны так же, как ролики, и нужны по отдельности: из карусели в семь
кадров может понадобиться три, а не все семь.

Действующее расширение видит только видео и умеет сохранять ровно один файл за
нажатие. Карусели в нём отсутствуют как понятие.

## Решение

Ядро переводится с плоского списка роликов на модель «пост со слайдами». Reels
и одиночная картинка становятся частным случаем: пост с одним слайдом. Всё
остальное — определение цели на экране, кнопки, имена файлов, дедупликация —
надстраивается над этой моделью.

Принцип прежний и не обсуждается: расширение не делает ни одного запроса к
Instagram. Оно читает только то, что страница уже получила для показа. Там, где
в данных лежит лишь мелкое превью, файл сохраняется как есть, а тост говорит
его размер.

## Модель данных

```js
{
  code: 'DKx9dQ2',        // короткий код поста, основной ключ
  pk: '3412345678901234567',
  username: 'nike',
  takenAt: 1785542400,    // unix seconds, UTC
  slides: [
    { index: 1, kind: 'image', sources: [{ url, width, height }, ...] },
    { index: 2, kind: 'video', sources: [{ url, width, height }, ...] }
  ]
}
```

`index` начинается с единицы и совпадает с порядком в карусели, потому что
именно этот номер человек видит на экране и ожидает в имени файла.

`sources` — все варианты одного слайда, от которых при сохранении берётся самый
крупный по площади.

## Что меняется в `src/lib/extract.js`

Файл остаётся единственным местом с чистой логикой и единственным, покрытым
тестами.

| Функция | Что с ней |
|---|---|
| `collectMedia(payload)` | Отдаёт посты со слайдами вместо плоского списка роликов. Форма результата меняется, тесты переписываются |
| `bestSource(sources)` | Заменяет `bestVideo`. Логика та же: наибольшая площадь |
| `buildFilename(post, slide)` | Принимает пост и слайд, ставит номер и расширение |
| `readAudio(node)` | Новая. Прямой адрес звуковой дорожки, если он есть в данных |
| `mediaKeyFromUrl(url)` | Новая. Стабильный ключ файла на CDN |
| `extensionFromUrl(url, kind)` | Новая. Расширение файла из адреса |
| `sanitizeSegment`, `formatDate`, `codeFromPath`, `isDirectVideoUrl` | Без изменений |

`bestVideo` удаляется, а не оставляется синонимом: он вызывается из одного
места в `content.js`, и два имени для одного действия пережили бы ровно один
рефакторинг.

### Сбор слайдов

Обход по-прежнему идёт по признаку, а не по фиксированному пути внутри ответа.
Признаков теперь три: у объекта есть видео (`video_versions`, `video_url`),
картинки (`image_versions2.candidates`, `display_url`, `display_resources`) или
дети (`carousel_media`, `edge_sidecar_to_children.edges[].node`).

Узел с детьми — это пост-карусель. Его дети разворачиваются в слайды по порядку
и **не** попадают в результат как самостоятельные посты: иначе семь кадров
превратились бы в семь безымянных постов без автора и порядка. Обход помечает
их как разобранные и не возвращается к ним.

Узел без детей, но с медиа — пост с одним слайдом.

Один и тот же пост приходит в нескольких ответах, и приходит разной полноты:
в ленте без части полей, на своей странице целиком. Поэтому посты с одинаковым
ключом сливаются: побеждает тот набор слайдов, который длиннее, а недостающие
автор и дата добираются из любого экземпляра, где они есть. Это правило уже
работает для роликов (`mergeItem`) и распространяется на слайды.

Ограничители обхода (`MAX_NODES`, защита от циклов) сохраняются как есть.

### Имя файла

```
nike — 2026-08-01 — DKx9dQ2.jpg          одиночная картинка
nike — 2026-08-01 — DKx9dQ2 — 3.jpg      третий слайд карусели
nike — 2026-08-01 — DKx9dQ2.mp4          Reels, как было
```

Номер слайда добавляется только когда в посте больше одного слайда. Правило
пропуска неизвестных кусков (автор, дата) остаётся прежним.

Расширение берётся из пути адреса, если оно входит в список
`jpg, jpeg, png, webp, heic, mp4`. Иначе `.jpg` для картинки и `.mp4` для видео.
Query-часть адреса на расширение не влияет: у Instagram там подписи и параметры
размера.

### Ключ файла на CDN

У Instagram последний сегмент пути стабилен и не зависит от размера картинки:

```
https://scontent-xyz.cdninstagram.com/v/t51.2885-15/12345678_901234_5678_n.jpg?stp=dst-jpg_e35_p1080x1080&_nc_ht=…
                                                    ^^^^^^^^^^^^^^^^^^^^^^^^^^ ключ
```

Размер живёт в `stp`, подпись в `oh` и `oe`, и всё это меняется от запроса к
запросу. Сам файл — нет. `mediaKeyFromUrl` возвращает этот сегмент, и по нему
картинка на экране находит свой слайд в перехваченных данных.

## Кэш в `content.js`

Сегодня кэш — это `код → ролик`, и запись без кода отбрасывается. Такой кэш
потерял бы сторис целиком, а поиск слайда по картинке на экране требовал бы
перебора всех постов на каждое движение мыши.

Кэш становится двумя картами:

- `посты`: `код или pk → пост со слайдами`;
- `ключи`: `ключ файла на CDN → (код или pk, номер слайда)`.

Вторая карта заполняется при каждом попадании медиа в кэш и делает поиск цели
одним обращением. Обе живут в памяти вкладки и умирают вместе с ней: истории
между сессиями расширение по-прежнему не ведёт.

## Определение цели на экране

**Шаг 0. Открыт ли пост.** Сохранение работает только на открытом посте.
Признак — код в адресе страницы: Instagram ставит `/p/<код>/` и когда пост
распахнут модальным окном поверх ленты или профиля. Запасной признак для
редких случаев без смены адреса — медиа внутри `div[role="dialog"]`.

В ленте и в сетке профиля кнопки нет намеренно. Под курсором там миниатюра,
файл из неё вышел бы хуже оригинала, а какой пост имеется в виду — вопрос
догадки. Обиход всё равно начинается с открытия поста целиком.

**Шаг 1. Какой элемент.** Самый крупный видимый постовой медиа-элемент.
Постовым считается `<video>` либо `<img>`, у которого адрес ведёт на
`cdninstagram.com` или `fbcdn.net`, а меньшая сторона на экране не меньше
180 CSS-пикселей. Порог отсекает аватарки (150 px в шапке профиля на
десктопе) и иконки.

**Шаг 2. Какой слайд.** По `mediaKeyFromUrl` от `currentSrc` элемента ищется
совпадение в кэше. Совпало — известны и пост, и номер слайда. Запасные пути в
порядке убывания надёжности: параметр `img_index` из адреса страницы, позиция
`<li>` внутри карусели, первый слайд.

Подсветки цели нет. На открытом посте цель одна и очевидна без неё.

## Кнопки

Круглая кнопка сохраняет то, что сейчас на экране: одиночную картинку, открытый
слайд карусели или ролик. Один кадр за нажатие, пакетного сохранения нет.
Нужны три слайда из семи — листаешь и жмёшь три раза, и ровно эти три и
сохраняются.

Слева от неё кнопка с нотой, когда у поста есть звук.

Кнопки скрыты, пока пост не открыт. Иконка расширения в панели Chrome
работает как раньше и сохраняет текущий кадр: это запасной путь на случай,
если кнопка не отрисуется.

## Результат на диске

| Что | Куда |
|---|---|
| Видео | `Загрузки/Reels` |
| Картинки | `Загрузки/Photos` |
| Звук | `Загрузки/Audio` |

Раздельные папки выбраны, чтобы уже собранный архив роликов не размывался, а
имя папки не начинало врать. Ранее скачанное не трогается и никуда не переносится.

Повтор ловится ключом `код#слайд`. У поста с одним слайдом ключ остаётся просто
кодом, поэтому сохранённые ранее Reels не поедут заново. Если кода нет
(случается у сторис), ключом становится `pk`.

Предупреждение о качестве: если у выбранного варианта картинки большая сторона
меньше 1080 px, тост говорит фактический размер и советует открыть пост.
Например: `640 px — открой пост для полного качества`. Файл при этом
сохраняется, решение остаётся за человеком. Когда размеры в данных не указаны,
предупреждения нет: врать про неизвестное хуже, чем молчать.

## Звук отдельным файлом

Кнопка с нотой забирает только звуковую дорожку. Появляется, когда текущий
слайд — видео либо когда к посту прикреплена музыка: фотопост с музыкой звук
тоже отдаёт.

Два источника, в порядке предпочтения.

**Прямой адрес дорожки.** У Reels в данных обычно лежит готовый адрес звука:
`clips_metadata.original_sound_info.progressive_download_url` для оригинального
звука и `music_info.music_asset_info.progressive_download_url` для
лицензированной музыки. Когда он есть, файл скачивается как любой другой, без
обработки. Оговорка: у лицензированной музыки по этому адресу часто лежит
отрывок, а не трек целиком. Это свойство данных Instagram, а не наше решение.

**Разбор mp4.** Когда прямого адреса нет, ролик забирается в память и из него
вынимается звуковая дорожка без перекодирования: контейнер пересобирается в
`m4a`, сами звуковые кадры копируются байт в байт. Качество равно исходному,
потому что ничего не декодируется.

Разбор живёт в отдельном чистом модуле `src/lib/mp4audio.js` под тестами. Он не
знает ни про DOM, ни про сеть: на вход `ArrayBuffer`, на выход `Uint8Array`
либо внятная ошибка. Поддерживается обычный прогрессивный mp4 — именно такой
Instagram отдаёт в `video_versions`. Фрагментированный mp4, отсутствие звуковой
дорожки и битый контейнер дают отказ с текстом, а не молчание и не файл-обманку.

Готовый `m4a` уходит в загрузку через `data:`-адрес. Так сохраняется подпапка:
`URL.createObjectURL` в service worker MV3 недоступен, а через `<a download>`
файл лёг бы в корень Загрузок.

Имя строится как у остального: `nike — 2026-08-01 — DKx9dQ2.m4a`. Название
трека в имя не идёт: для архива референсов важнее, из какого поста звук.
Ключ дедупликации — обычный ключ слайда с хвостом `#audio`.

## Сторис

Отдельного кода не требуют. Элементы сторис приходят тем же перехватчиком и
имеют те же поля (`image_versions2`, `video_versions`, `taken_at`, `user`), а
сопоставление по ключу CDN работает независимо от того, откуда картинка.

Единственная особенность — код поста может отсутствовать, поэтому ключом
дедупликации становится `pk`, а в имени файла место кода занимает он же.
Сторис ложатся в те же `Photos` и `Reels`: отдельная папка под исчезающий
контент не окупается.

Форма данных сторис не проверена живьём и остаётся риском. Поэтому сторис идут
последней фазой: если структура окажется иной, две первые фазы уже работают.

## Ошибки

| Ситуация | Поведение |
|---|---|
| Пост не открыт, либо на экране нет постового медиа | Кнопок нет |
| Цель есть, данных о ней нет | `Источник не найден. Обнови страницу и попробуй снова.` |
| Слайд не сопоставился ни одним способом | Сохраняется первый слайд, тост честно говорит: `Слайд не опознан, сохранил первый` |
| Лучшее качество меньше 1080 px | Файл сохраняется, тост называет размер |
| Файл уже сохранён | `Этот слайд уже сохранён` |
| Загрузка отклонена или прервана | Прежний запасной путь: файл забирается внутри страницы, ложится в корень Загрузок, тост об этом говорит |
| В ролике нет звуковой дорожки | `В этом ролике нет звука` |
| Контейнер фрагментированный или битый | `Не смог разобрать звук в этом ролике` |

Молчаливых отказов нет ни в одной ветке. Это правило из первой спеки
распространяется на всё новое.

## Порядок работ

Три фазы, каждая заканчивается рабочим расширением.

**Фаза 1. Ядро и открытый пост.** Модель слайдов в `extract.js` с тестами,
сопоставление по ключу CDN, папка `Photos`, дедупликация по слайдам.
Проверяется на открытом посте: одиночная картинка, карусель, смешанная карусель,
Reels не сломался.

**Фаза 2. Сторис.** Разбор при отличиях в форме данных, `pk` вместо кода.

**Фаза 3. Звук.** Прямой адрес дорожки, разбор mp4 в `m4a`, кнопка с нотой.

Фаза «лента и сетка профиля» была реализована и снята 04.08.2026 по итогам
живого прогона, см. пересмотр в начале документа.

## Сопутствующее

Манифест новых разрешений не требует: `downloads`, `storage` и хосты CDN уже
на месте. Меняются только название действия кнопки, описание расширения и
версия — `0.2.0`.

README переписывается в том же коммите: раздел «Как пользоваться» получает
картинки и карусели, раздел «Границы» — новую редакцию.

## Проверка

Юнит-тесты на `extract.js`, поверх существующих:

- карусель разворачивается в слайды с верным порядком и типами;
- дети карусели не всплывают как отдельные посты;
- старая схема `edge_sidecar_to_children` разбирается наравне с `carousel_media`;
- пост с одной картинкой даёт один слайд;
- смешанная карусель сохраняет тип каждого слайда;
- `mediaKeyFromUrl` даёт один ключ для одного файла в разных размерах и `null` на мусоре;
- `extensionFromUrl` разбирает адрес с query и падает на умолчание при незнакомом расширении;
- имя файла с номером слайда и без него;
- `bestSource` выбирает наибольший вариант;
- разбор Reels даёт тот же результат, что до изменений;
- у звука своё умолчание расширения и свой набор известных;
- адрес звуковой дорожки читается из обоих мест: оригинальный звук и музыка;
- разбор боксов mp4 находит звуковую дорожку и её кадры;
- пересобранный `m4a` разбирается обратно и содержит те же байты кадров;
- фрагментированный контейнер и ролик без звука дают ошибку, а не файл-обманку.

Ручной прогон делает Антон, по одной фазе за раз, по списку мест из фазы.

## Границы

Сохранение работает только на открытом посте и только по одному кадру за
нажатие. В ленте и в сетке профиля кнопки нет.

Не делается: пакетное сохранение карусели, очередь загрузок, история в
интерфейсе, выбор качества руками, сохранение обложек и превью отдельно от
поста, скачивание закреплённых альбомов целиком, автообновление, публикация в
Chrome Web Store.

Звук не перекодируется. Ни mp3, ни смена битрейта, ни обрезка: дорожка
копируется как есть. Лицензированная музыка сохраняется ровно в том объёме, в
каком её отдаёт Instagram.

Папка сохранения по-прежнему не настраивается: Chrome не разрешает расширению
писать за пределы папки загрузок.

Расширение не делает запросов к Instagram. Когда данных на странице нет, оно
говорит об этом, а не идёт за ними.

## Риски

Форма данных сторис не проверена.

Насколько часто у роликов есть прямой адрес звука, тоже выяснится живьём.
Разбор mp4 написан именно поэтому: он закрывает случай, когда адреса нет, и его
надёжность проверяется на настоящих файлах, а не на предположении о них.

Диагностика прежняя: `localStorage.reelboxDebug = '1'` печатает в консоль, что
именно нашлось. Чинится по-прежнему один файл — `extract.js`.
