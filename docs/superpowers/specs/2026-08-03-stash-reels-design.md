# Stash — сохранение Reels в один клик

Дата: 2026-08-03
Статус: реализовано, проверено живьём 2026-08-03

## Задача

Антон смотрит Instagram в Chrome на маке и собирает Reels как референсы.
Нужен способ сохранить открытый ролик в виде чистого mp4 без лишних движений
и без сторонних сайтов-скачивалок.

## Решение

Распакованное расширение Chrome (Manifest V3), которое ставится локально через
`chrome://extensions` в режиме разработчика. Работает только на instagram.com.

Расширение берёт ту прямую ссылку на mp4, которую плеер Instagram и так
загружает, чтобы показать ролик. Никаких дополнительных запросов к Instagram,
никакой работы с чужой сессией: используется то, что уже пришло в браузер.

### Почему не отдельное приложение с yt-dlp

Внешняя качалка упирается в требование залогиненной сессии и в передачу ей
cookies. Расширение работает внутри уже залогиненной вкладки, поэтому этот
класс отказов исчезает.

Цена решения: Chrome разрешает расширению сохранять файлы только внутри своей
папки загрузок. Отсюда фиксированная папка `Загрузки/Reels`.

## Как устроено

Четыре части.

**`src/lib/extract.js`** — чистые функции без обращений к браузеру. Разбор
произвольного JSON в поисках вариантов видео, выбор лучшего качества, сборка
имени файла, вытаскивание кода ролика из адреса страницы. Единственная часть,
покрытая юнит-тестами.

**`src/interceptor.js`** — работает в контексте самой страницы (`world: MAIN`).
Оборачивает `fetch` и `XMLHttpRequest`, читает копию ответа, отдаёт найденные
записи в контент-скрипт через `postMessage`. Оригинальный ответ страницы не
изменяется ни при каких условиях: любая ошибка внутри перехватчика гасится и
не доходит до Instagram.

**`src/content.js`** — контент-скрипт. Держит кэш «код ролика → ссылка, автор,
дата», рисует кнопку в Shadow DOM, определяет текущий ролик, инициирует
сохранение и показывает состояние.

**`src/background.js`** — service worker. Вызывает `chrome.downloads`, помнит
уже сохранённые коды в `chrome.storage.local`, обрабатывает нажатие иконки в
панели, следит за прерванными загрузками.

### Устойчивость к изменениям Instagram

Три независимых источника ссылки, в порядке убывания надёжности:

1. Перехваченные ответы API (основной путь).
2. JSON, вшитый в HTML страницы при первой загрузке (`script[type="application/json"]`).
3. Прямой `src` элемента `video`, если он не `blob:`.

Поиск внутри JSON идёт не по фиксированному пути, а обходом всей структуры по
признаку «объект содержит `video_versions` или `video_url`». Переименование
обёртки или добавление уровня вложенности такой поиск переживает.

Два независимых способа запустить сохранение: кнопка поверх плеера и иконка
расширения в панели Chrome. Если Instagram сменит вёрстку и кнопка не
отрисуется, иконка продолжит работать.

### Определение текущего ролика

Основной сигнал — адрес страницы: в ленте Reels он меняется при прокрутке.
Разбираются формы `/reel/<code>/`, `/reels/<code>/`, `/p/<code>/`, `/tv/<code>/`
и варианты с именем автора перед ними. Запасной сигнал — ближайшая к самому
видимому в окне видео ссылка на пост.

## Результат на диске

Один файл в максимальном доступном разрешении, папка `Загрузки/Reels`,
имя вида `nike — 2026-08-01 — DKx9dQ2.mp4`: автор, дата публикации, короткий
код ролика. Дата берётся в UTC, чтобы имя не зависело от часового пояса.
Если автор или дата неизвестны, соответствующий кусок имени опускается.

Повторное сохранение того же ролика не создаёт копию с суффиксом: расширение
помнит сохранённые коды и сообщает, что файл уже есть.

## Ошибки

| Ситуация | Поведение |
|---|---|
| Код ролика не определяется | Кнопка сообщает: открой сам ролик |
| Ссылки нет ни в одном источнике | Кнопка сообщает: обнови страницу |
| Загрузка отклонена или прервана | Запасной путь: файл забирается внутри страницы и отдаётся в загрузку оттуда, при этом он попадает в корень Загрузок, о чём кнопка честно говорит |
| Запасной путь тоже не прошёл | Текст ошибки в кнопке, подробности в консоли |

Молчаливых отказов нет ни в одной ветке.

## Границы

Не делается: очередь, история скачиваний, выбор качества, карусели, сторис,
пакетная обработка, автообновление, публикация в Chrome Web Store.

Видео из обычных постов, скорее всего, заработает тем же механизмом, но это
не заявленная функция и не проверяется.

## Проверка

Юнит-тесты (`node --test`) на `extract.js`: поиск вариантов видео во
вложенной структуре, устойчивость к мусору и циклам, выбор лучшего качества,
разбор адреса, сборка и очистка имени файла.

Ручной прогон на трёх местах: лента `/reels/`, отдельная страница ролика,
ролик, открытый из профиля.

## Живая проверка

2026-08-03: расширение установлено и проверено на реальных роликах, сохранение
работает. Форма данных Instagram совпала с ожидаемой, правки `extract.js` не
потребовались.

Остаточный риск прежний: Instagram может изменить форму ответов, и тогда
перестанет находиться ссылка. Диагностика на этот случай встроена, режим
отладки включается через `localStorage.stashDebug = '1'` и печатает в
консоль, что именно нашлось. Чинится только `extract.js`.
