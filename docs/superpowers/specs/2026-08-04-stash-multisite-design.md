# Stash — TikTok и YouTube

Дата: 2026-08-04
Статус: Instagram и TikTok реализованы; YouTube упёрся в SABR, см. ниже

Продолжение [2026-08-03-stash-images-design.md](2026-08-03-stash-images-design.md).
Там описано сохранение из Instagram, здесь — выход на другие площадки и
переименование инструмента.

## Задача

Референсы Антон собирает не только в Instagram. Нужны TikTok (видео,
фото-слайдшоу, звук) и YouTube (обычные ролики и Shorts, видео со звуком и
звук отдельно).

Действующее расширение знает только словарь полей Instagram, а определение
«что сейчас на экране» вшито в его вёрстку.

## Имя

Инструмент переименован из Reelbox в **Stash**. Прежнее имя привязано к формату
одной площадки, а инструмент перестал быть про неё.

Переименование стоило памяти о скачанном: распакованное расширение получает
идентификатор от пути к папке, папка переехала в `projects/stash`, поэтому
`chrome.storage.local` начался с нуля. Потеря невелика, дедупликация просто
считает заново.

## Решение

Один обходчик, несколько словарей. Ядро остаётся общим: обход произвольного
JSON, слияние постов, имена файлов, ключи CDN, папки, дедупликация. Всё, что
знает про конкретную площадку, выносится в отдельный файл-словарь.

```
src/lib/extract.js        общий обходчик и имена, площадок не знает
src/lib/sites/instagram.js  поля Instagram + правила «открыт ли пост»
src/lib/sites/tiktok.js     то же для TikTok
src/lib/sites/youtube.js    то же для YouTube
```

Словарь площадки отвечает на один и тот же набор вопросов: как из узла достать
видео, картинки, детей-слайды и звук; как понять автора, дату и код; открыт ли
сейчас пост и какой элемент на экране считать постовым. Площадка выбирается по
имени хоста один раз при запуске.

Принцип прежний и на новых площадках не меняется: **ни одного собственного
запроса к площадке**. Читаем только то, что страница уже получила.

## TikTok

Данные приходят двумя путями, оба уже поддержаны: ответы API ловит
перехватчик, а при первой загрузке страницы всё лежит в инлайновом JSON
(`__UNIVERSAL_DATA_FOR_REHYDRATION__`, у старых сборок `SIGI_STATE`).

Словарь полей:

| Что | Где |
|---|---|
| Видео | `video.playAddr`, варианты в `video.bitrateInfo[].PlayAddr.UrlList[]` |
| Картинки слайдшоу | `imagePost.images[].imageURL.urlList[]` |
| Звук | `music.playUrl` |
| Автор | `author.uniqueId` |
| Дата | `createTime` (unix seconds) |
| Код | `id` |

Берём `playAddr`, а не `downloadAddr`: во втором варианте TikTok впечатывает
водяной знак.

Звук у TikTok лежит отдельным готовым файлом, поэтому разбор mp4 для него не
нужен. Разбор остаётся запасным путём на случай, если `music.playUrl` пуст.

Открытый пост опознаётся по адресу: `/@автор/video/<id>` и `/@автор/photo/<id>`.
В ленте кнопки нет, как и в Instagram.

**Ожидаемая грабля с Referer.** Часть CDN TikTok отдаёт файлы только
запросам с правильным `Referer`, а загрузка из service worker его не ставит.
Насколько это заденет нас, заранее неизвестно, поэтому отдельного обходного
пути не закладываем: у расширения уже есть запасной путь через страницу, и он
включится сам, если основной откажет. Цена запасного пути одна — папку задать
нельзя, файл ложится в корень Загрузок, и тост об этом говорит.

## YouTube: не поддержан

Реализовано и снято 04.08.2026 по итогам живого прогона. Здесь остаётся только
причина, чтобы не заходить сюда второй раз.

Замысел был такой: готовых ссылок на файлы YouTube почти не отдаёт, адреса
закрыты подписью, но расшифровывать её не нужно — плеер уже подписал их сам,
чтобы проиграть ролик, и достаточно взять готовое.

**Не работает.** Наблюдение за запросами вкладки включилось и поймало
настоящие обращения плеера. Ни одно не является адресом файла:

```
expire,ei,ip,id,source,requiressl,xpc,cps,met,mh,mm,mn,ms,mv,mvi,pl,rms,
initcwndbps,siu,spc,svpuc,ns,sabr,rqh,mt,fvip,keepalive,fexp,c,n,sparams,
sig,lsparams,lsig,cpn,cver,rn,alr
```

Нет ни `itag`, ни `clen`, ни `mime`, зато есть `sabr`. Это SABR: `videoplayback`
больше не ссылка на файл, а конец потока. Плеер шлёт туда POST с двоичным
запросом, где сам описывает нужный формат и диапазон байт, а сервер отвечает
собственным кадрированным форматом, из которого содержимое ещё надо извлечь.

Адреса из `streamingData` при этом отвечают `403`: у них нет `pot`, токена
подтверждения происхождения. Плеер добавляет его в момент запроса, в данных
его нет, вычислить мы его не можем.

Значит поддержка YouTube требует либо разбора протокола SABR, либо запроса
данных под другим клиентом InnerTube — то есть собственного обращения к
YouTube, чего мы на других площадках избегаем. Оба пути дороги, второй ещё и
ненадёжен: этот слой YouTube закрывает прямо сейчас.

Решение: YouTube не поддерживается. Код удалён, чтобы не изображать
поддержку, которой нет.

Вместе с ним удалён `src/lib/mp4mux.js` — сборка раздельных потоков видео и
звука в один mp4 с разбором фрагментированного контейнера. Он был написан
только под YouTube, работал и был покрыт тестами. Если поддержка когда-нибудь
вернётся, брать его из истории, коммит `cb824ac`.

## Результат на диске

| Что | Куда |
|---|---|
| Видео | `Загрузки/Reels` |
| Картинки | `Загрузки/Photos` |
| Звук | `Загрузки/Audio` |

Папки общие для всех площадок: архив собирается по типу материала, а не по
тому, откуда он взят. Имя файла по-прежнему `автор — дата — код.расширение`.

## Ошибки

| Ситуация | Поведение |
|---|---|
| Площадка не поддержана | Кнопок нет |
| Ролик не открыт | Кнопок нет |
| YouTube: подходящих потоков не нашлось | `Потоки закрыты подписью. Включи воспроизведение и попробуй снова` |
| YouTube: звук и видео в несовместимых контейнерах | Два файла и прямое сообщение об этом |
| TikTok: отказ CDN на основном пути | Тихо уходит на запасной, тост называет корень Загрузок |

Молчаливых отказов нет ни в одной ветке.

## Порядок работ

**Фаза 1. Словари.** Общий обходчик отделяется от полей Instagram, тесты
переезжают на новую границу, поведение не меняется.

**Фаза 2. TikTok.** Словарь, правила открытого поста, живой прогон.

**Фаза 3. YouTube, звук.** Перехват `videoplayback`, выбор звукового потока,
кнопка ноты.

**Фаза 4. YouTube, видео.** Прогрессивный формат, затем сборка двух потоков в
`mp4mux.js`.

Прогрессивный формат берётся, только когда он не хуже раздельных. У YouTube
это обычно 360p, и молча отдать его вместо собранного 1080p нельзя.

## Границы

Сохранение по-прежнему по одному материалу за нажатие и только на открытой
странице ролика или поста.

Не делается: обход подписей и защиты, выбор качества руками, перекодирование,
плейлисты целиком, субтитры, обложки отдельно от ролика.

Публикация в Chrome Web Store не планируется. Инструмент личный, и это не
формальность: сборка двух потоков в один файл на YouTube — та часть, которая в
чужих руках выглядит иначе, чем в своих.
