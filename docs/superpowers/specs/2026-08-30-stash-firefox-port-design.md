# Stash — сборка под Firefox и раздача со своего сайта

Дата: 2026-08-30
Статус: пакет собирается и проходит линтер, подпись в Mozilla не подавалась

## Задача

Расширение ставилось только распакованным, с включённым режимом разработчика и
обновлением руками. Это годится для инструмента «для себя» и не годится для
продукта, который можно кому-то показать.

Chrome такой возможности не даёт вовсе: установка `.crx` мимо Web Store на
macOS и Windows заблокирована, а публиковать в Web Store нельзя — его политика
прямо запрещает расширения, дающие доступ к контенту за логином, и называет
загрузку видео примером нарушения.

Firefox даёт. Mozilla подписывает расширение в режиме unlisted: у себя не
публикует, но подписанный XPI ставится с любого сайта одним нажатием и дальше
обновляется сам.

## Решение

### Манифест один

`manifest.json` остаётся тем, что лежит распакованным для Chrome. Вариант для
Firefox получается из него правкой в `scripts/build.py`, вторым файлом не
хранится: два манифеста разъехались бы на первом же новом разрешении ровно
так же, как разъехались бы имена папок из соседней спеки.

Правка состоит из трёх вещей.

`background.service_worker` заменяется на `background.scripts`: Firefox
service worker в фоне не поддерживает (баг 1573659) и ждёт обычный фоновый
скрипт.

`browser_specific_settings.gecko` получает `id`, без которого расширение
нельзя ни подписать, ни обновлять, и `update_url` на свою карту обновлений.
Для расширения, размещённого у Mozilla, `update_url` запрещён, поэтому подача
обязана быть unlisted.

`data_collection_permissions: { required: ["none"] }` — обязательное для новых
расширений заявление о том, какие данные собираются. Stash не собирает
никаких.

### Порог версии Firefox

`strict_min_version` — 140.0, и это максимум из трёх ограничений. Firefox 127
первым стал показывать `host_permissions` в окне установки и выдавать их
сразу: ниже этой границы человек поставил бы расширение, которое молча ничего
не делает. Firefox 128 — первая версия с `world: "MAIN"`, без которого
перехватчик не попадёт в контекст страницы. Firefox 140 — первая, которая
понимает `data_collection_permissions`; ниже ключ игнорируется, и заявление о
несборе данных до человека не доедет.

Для Android объявлен свой порог, 142.0. Раздача со своего сайта на Android не
работает вовсе, а Stash — инструмент настольный; порог указан только затем,
чтобы заявление о данных было честным и там.

### Одна строка вместо двух наборов вызовов

Единственное различие между сборками в коде — то, что Firefox отдаёт промисы
через `browser`, а Chrome через `chrome`. Снято строкой
`const api = globalThis.browser || globalThis.chrome` в трёх файлах, которые
трогают API: `background.js`, `content.js`, `options/options.js`. Ядро
`extract.js` API не трогает вовсе и остаётся общим без оговорок.

### Что нашёл линтер

`web-ext lint --self-hosted` поймал три вещи, которые иначе уехали бы в
Mozilla вслепую.

Отсутствие `data_collection_permissions` — теперь объявлено.

Присваивание `innerHTML` в `content/ui.js` при каждой смене состояния кнопки:
иконка пересобиралась из разметки. Заменено на хранение узлов и
`replaceChildren`. Разметка там была статической, инъекции не было, но
пересборка HTML на каждое нажатие была лишней и сама по себе.

`update_url` линтер считает ошибкой по умолчанию, потому что для размещённых у
Mozilla расширений он запрещён. С флагом `--self-hosted` ошибка снимается, и
это же напоминание, что подача обязана быть unlisted.

Итог: ноль ошибок, ноль предупреждений.

## Границы

Подпись в Mozilla не подавалась, страница на сайте не сделана. Сервер обязан
отдавать XPI с `Content-Type: application/x-xpinstall`, иначе Firefox
предложит скачать файл вместо установки.

Живьём в Firefox сборка не запускалась. Отдельно стоит проверить сохранение
звука: оно уходит в загрузку `data:`-адресом, а Firefox известен отказами на
`blob:`-адресах в `downloads.download`. Если откажет и на `data:`, сработает
уже существующий запасной путь — файл отдаётся из страницы, — но ляжет он в
корень загрузок, без подпапки.

Safari не делается. Порт возможен: `world: "MAIN"` поддержан с Safari 18, а
Safari 18.4 впервые разрешил расширения, подписанные Developer ID и заверенные
у Apple, то есть без App Store. Но это нативная обёртка, Xcode и 99 долларов в
год Apple, и решение отложено.
